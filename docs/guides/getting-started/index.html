설치·부팅 시작 안내서

의존성 설치부터 .env, Redis/MySQL, 첫 서버 실행과 다음 학습 경로를 설명합니다.

이 저장소의 조립 방식

명시적 INSTALLED_APPS: config.INSTALLED_APPS가 설치 대상을 선언하고 App Registry가 해당 목록만 배선합니다.

Python 요구 버전, 의존성, Redis·MySQL 준비, .env, 실행 명령은 아래 README의 빠른 시작 절에서 그대로 가져왔습니다.

빠른 시작

git clone https://github.com/bluebamus/fastapi-project-structure-django-passive-style.git
cd fastapi-project-structure-django-passive-style

이후 모든 명령은 저장소 루트에서 실행합니다.

0단계 — .env 준비

uv sync
cp .env.example .env        # PowerShell: Copy-Item -LiteralPath .env.example -Destination .env
uv run python -c "import secrets; print(secrets.token_urlsafe(48))"   # 키마다 한 번씩, 세 번 실행

.env 에서 아래를 바꿉니다. 바꾸지 않으면 개발 환경에서도 기동하지 않습니다(설정 검증). 오류 메시지에 고칠 설정 이름이 나오므로 그대로 따라 고치면 됩니다.

설정 할 일
ACCESS_TOKEN_SECRET_KEY·REFRESH_TOKEN_SECRET_KEY·SESSION_SECRET_KEY 위 명령으로 만든 값을 서로 다르게 넣는다(32자 이상)
MYSQL_PASSWORD 2단계에서 띄울 MySQL 의 비밀번호와 같은 값. 비워 두거나 예시 값이면 거부

.env 가 없으면 기동하지 않습니다. 파일 없이 환경 변수로 주입하는 경우(컨테이너)는 ENV·비밀 키 3종· MYSQL_HOST/USER/PASSWORD/DATABASE 가 모두 있어야 합니다. 테스트(ENV=test, pytest 가 지정)는 이 검증을 하지 않습니다.

1단계 — Redis 만으로 HTTP 배선 확인

앱은 기동할 때 REDIS_HOST/REDIS_PORT 로 ping() 하고, 실패하면 시작하지 않습니다(DEBUG 와 무관). 이어서 INFO server 의 버전이 7.0 미만이면 시작하지 않습니다(INFO 를 막아 둔 관리형 Redis 는 WARNING 만 남기고 계속). MySQL 없이 배선을 보려면 DEBUG=false 로 개발용 테이블 생성을 끕니다.

docker run --rm -d --name fastapi-redis -p 6379:6379 redis:7-alpine   # 7.0 이상 (EXPIRE NX)
DEBUG=false uv run uvicorn main:app --port 8000
curl http://127.0.0.1:8000/health
# {"status":"healthy","version":"1.0.0"}   ← .env.example 의 VERSION

PowerShell:

$env:DEBUG = "false"
uv run uvicorn main:app --port 8000
Remove-Item Env:DEBUG      # 끝난 뒤 개발 기본값으로 복원
이 상태에서 결과 이유
GET /health 200 DB 를 보지 않는다
GET /ready 503 writer DB 의 SELECT 1 이 실패한다(Redis 는 기동 조건이라 이미 응답한다)
기능 API (GET /api/v1/blog/posts 등) 500 MySQL 이 필요하다
/docs, /openapi.json 404 DEBUG=false 가 문서를 끈다

API 문서를 보려면 DEBUG=true 여야 하고, DEBUG=true 는 MySQL 을 요구합니다 — 첫 실행에서 가장 헷갈리는 지점입니다.

2단계 — MySQL 추가

DEBUG=true(기본값)면 startup 에서 설치 앱이 소유한 테이블을 create_all 로 만듭니다. 그래서 설정 없이 uvicorn main:app 만 실행하면 MySQL 이 없어 startup 이 실패합니다((2003, "Can't connect to MySQL server ...")).

docker run -d --name fastapi-mysql -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD='<.env 의 MYSQL_PASSWORD 와 같은 값>' -e MYSQL_DATABASE=fastapi_db mysql:8.4
uv run uvicorn main:app --reload --port 8000

기본값(MYSQL_HOST=localhost, MYSQL_USER=root, MYSQL_DATABASE=fastapi_db)에 맞춘 로컬 전용 예시입니다. 빈 비밀번호는 개발 환경에서도 설정 검증이 거부하므로 비밀번호를 지정합니다. MySQL 8.4 의 기본 인증은 의존성의 cryptography 가 처리합니다. 문자셋을 직접 만들 때는 CREATE DATABASE fastapi_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci; 를 씁니다.

  • API 문서: http://127.0.0.1:8000/docs · 관리 화면: http://127.0.0.1:8000/admin (먼저 첫 관리자 만들기로 슈퍼유저를 만들고 그 계정으로 로그인) · 헬스체크: /health, /ready
  • 운영처럼 스키마를 Alembic 으로 관리하려면 uv run alembic upgrade head 후 DEBUG=false 로 실행합니다.

환경 변수 — 처음에 알아야 할 것

설정은 프로세스 환경변수 → 작업 디렉터리의 .env → 코드 기본값 순으로 읽습니다. .env.example 은 복사용 전체 목록이며 자동으로 읽히지 않습니다.

복사하는 방법은 0단계에 있습니다. 비밀번호·비밀키 예시값은 설정 검증이 잡는 placeholder 입니다 — ENV=test 가 아니면 (개발 환경 포함) 그대로 둔 채로는 기동하지 못합니다.

변수 기본값 의미
TRUSTED_PROXY_HOPS 0 앞단 신뢰 프록시 단 수. 프록시 뒤 배포면 반드시 설정 — 운영 배포 체크리스트
ACCESS_LOG_RETENTION_DAYS 365 접속 로그 보존 일수. 매일 03:30(TIME_ZONE) Celery beat 가 이보다 오래된 행을 5,000행씩 지운다. 0 = 지우지 않음, 음수는 기동 실패. beat 를 띄워야 돈다 — 운영 배포 체크리스트
DEBUG true true = 개발 테이블 생성 + /docs 노출 + DEBUG 로그 / false = 모두 끔(스키마는 Alembic)
REDIS_HOST / REDIS_PORT / REDIS_DB localhost / 6379 / 0 startup ping()·버전 확인 대상. 연결 실패나 7.0 미만이면 서버가 뜨지 않는다
MYSQL_HOST / MYSQL_USER / MYSQL_PASSWORD / MYSQL_DATABASE localhost / root / 빈 값 / fastapi_db primary DB
ADMIN_DISABLED false false = /admin 마운트(활성 슈퍼유저 로그인 필요) / true = 관리 화면 자체가 없다(404, 응답 어디에도 경로·링크 없음, sqladmin 미로드). 예전 ADMIN 은 제거됐다 — 남아 있으면 기동 실패
ENV development production/staging 에서 DEBUG=true 이거나 LOG_LEVEL=DEBUG 면 설정 로드가 실패하고, /admin 세션 쿠키에 Secure 가 붙는다(HTTPS 전용). 비밀키 검증은 test 외 모든 ENV 에 적용된다(아래)
DB_ROUTER_ENABLED false 읽기/쓰기 분리는 선택 기능
ACCESS_TOKEN_SECRET_KEY / REFRESH_TOKEN_SECRET_KEY / SESSION_SECRET_KEY change-this-... test 외 모든 ENV(개발 포함)에서 placeholder(빈 값·your- 시작·change-this 포함)이거나 32자 미만이면 기동이 실패하고, access·refresh 키는 서로 달라야 한다. SESSION_SECRET_KEY 는 /admin 관리 세션 ID 를 Redis 키(admin:sess:{HMAC})로 바꾸는 HMAC 키다(바꾸면 모든 관리 세션이 끊긴다). 생성: uv run python -c "import secrets; print(secrets.token_urlsafe(48))"

/admin 은 활성 슈퍼유저만 들어갑니다. 로그인 화면(Bootstrap)에서 scripts/create_superuser.py 로 만든 계정으로 로그인하면 admin_session 쿠키(path /admin·SameSite=Strict·HttpOnly)가 발급되고, 권한은 매 요청 DB 로 다시 확인합니다. 쿠키에는 무작위 세션 ID 만 있고 내용은 Redis 에 있습니다 — 30분 동안 쓰지 않거나 로그인 후 8시간이 지나면 다시 로그인해야 하고, 로그아웃하거나 API·관리 화면에서 그 사용자를 강등·비활성화·삭제하면(또는 --set-password 로 비밀번호를 바꾸면) 세션이 즉시 지워집니다. 로그인·생성·수정·삭제·로그아웃 같은 상태를 바꾸는 요청은 모두 CSRF 토큰을 싣고(화면 스크립트가 자동으로 붙인다), 없거나 다르면 403 입니다. 로그아웃은 POST 전용입니다(GET 은 405). 날짜 필터는 같은 날·이후·이전과 기간(시작일~종료일, 양 끝 포함)을 고를 수 있습니다. 세션은 /admin 전용이며 API 인증(JWT Bearer)과 섞이지 않습니다. 설계·흐름도·문제 해결은 관리 화면 인증 가이드, 배포 체크리스트는 아키텍처 §11에 있습니다.

선택 기능(Celery worker, replica 라우팅, Alembic)은 기본 실행에 필요 없습니다 — 필요할 때 아키텍처 레퍼런스를 봅니다.

세션·토큰 만료

세션·토큰의 만료는 아래 네 설정이 정한다 — 이 표가 정본이고, 다른 문서는 이 표를 가리킨다.

대상 설정 기본값 뜻
/admin 관리 세션 — 절대 만료 ADMIN_SESSION_MAX_AGE_SECONDS 28800 (8시간) 로그인 시각부터 세며 요청이 있어도 연장되지 않는다(쿠키 Max-Age 도 이 값). 60 미만은 기동 실패
/admin 관리 세션 — 미사용 만료 ADMIN_SESSION_IDLE_SECONDS 1800 (30분) 마지막 요청부터 다시 센다. 절대 만료를 넘지 않는다. 60 미만이거나 절대 만료보다 크면 기동 실패
API 접근 토큰 (access) ACCESS_TOKEN_EXPIRE_MINUTES 15 (분) 발급 후 이 시간이 지나면 401. 즉시 폐기 목록은 없다 — 짧은 수명이 그 대신이다
API refresh 토큰 REFRESH_TOKEN_EXPIRE_DAYS 7 (일) refresh 수명이자 Redis 기록·폐기 표시 TTL

JWT 검증 설정(JWT_ISSUER·JWT_AUDIENCE·JWT_ALGORITHM(HS256/384/512)·JWT_LEEWAY_SECONDS)과 레이트 리밋 AUTH_LOGIN_*·AUTH_REGISTER_* 는 .env.example·아키텍처 §7에 있습니다.

테스트

uv run python -m pytest -m "not mysql and not browser"   # 외부 인프라 불필요 (SQLite·가짜 Redis)
uv run ruff check . && uv run ruff format --check . && uv run mypy .
uv run python -m scripts.review_gate --fast              # 게이트 일괄 (MySQL 통합·브라우저 테스트 제외)

커버리지는 게이트·CI 가 항상 측정해 출력하지만 하한(pyproject.toml 의 fail_under)은 기본 0 입니다 — 처음에는 기능이 동작하는지가 먼저이고, 필요해지면 그 값 하나만 올립니다(올리는 법은 개발 가이드 §6.1). mysql·browser 마커 테스트의 준비물과 CI 구성은 개발 가이드 §6에 있습니다.

전수 통합(e2e) — 실제 MySQL 8.4 복제(primary + GTID replica)·Redis 7.4·uvicorn·Celery worker·Chromium 위에서 모든 API operation·관리 뷰·태스크·Redis 키를 실행하고, 장애(Redis·MySQL·worker)를 주입합니다. 하네스가 compose 를 직접 띄우고 내리므로 명령은 하나입니다(Docker 가 필요합니다 — Windows 면 WSL 안의 Docker 를 wsl -e docker 로 씁니다):

REDIS_HOST=127.0.0.1 REDIS_PORT=16393 uv run python -m pytest -m e2e   # 포트 13341·13342·16393·18093 (127.0.0.1)

무엇을 보장하는지·새 API 를 추가하면 무엇을 해야 하는지는 개발 가이드 §6.6에 있습니다.

자주 막히는 지점

증상 원인 조치
startup 에서 Redis 연결 실패 Redis 미기동·주소·인증 오류 REDIS_HOST 등과 서버 확인. DEBUG=false 로 우회되지 않는다
startup 에서 Redis 6.x 는 지원하지 않는다 서버가 7.0 미만 — 레이트 리밋의 EXPIRE NX 가 문법 오류가 된다 Redis 7.0 이상으로 올린다
startup 에서 Can't connect to MySQL server DEBUG=true 가 테이블 생성을 시도 MySQL 을 띄우거나 DEBUG=false
/docs 가 404 DEBUG=false DEBUG=true (MySQL 필요)
기능 API 만 500, /ready 503 DB 없음 2단계 진행
새 기능 route 가 안 보임 INSTALLED_APPS 미등록 또는 <name>_router 이름 불일치 아래 절 참고. module 은 있는데 공개 이름이 없거나 import 가 깨지면 기동이 실패한다
.env 파일이 없고, 필수 설정이 … .env 가 없다 0단계. 컨테이너라면 메시지에 나온 환경 변수를 주입
기동 실패 (ADMIN 은 ADMIN_DISABLED 로 바뀌었다) 환경 변수나 .env 에 예전 ADMIN 줄이 남아 있다 ADMIN 이 false 였다면 ADMIN_DISABLED=true 로 바꾸고, true 였다면 그 줄을 지운다
/admin 로그인 후 다시 로그인 화면 staging/production 에서 HTTP 로 접속해 Secure 쿠키가 저장되지 않았다 / 계정이 슈퍼유저·활성이 아니다 HTTPS 로 접속(프록시 TLS 종단 포함). 계정은 scripts.create_superuser 로 승격
/admin 로그인이 429 ip 또는 ip+사용자명 시도 한도(AUTH_LOGIN_*) 초과. 프록시 뒤에서 TRUSTED_PROXY_HOPS=0 이면 모두가 한도를 나눠 쓴다 Retry-After 초만큼 기다린다. 프록시 뒤라면 TRUSTED_PROXY_HOPS 설정
기동 실패 (설정이 안전하지 않습니다) 비밀키·비밀번호가 placeholder·빈 값·32자 미만이거나 access·refresh 키가 같다(개발 환경 포함) / 배포 환경의 DEBUG=true 또는 LOG_LEVEL=DEBUG 메시지에 나온 설정을 고친다 — 비밀키는 secrets.token_urlsafe(48) 로 만든 서로 다른 값으로 교체, 인증 없는 Redis 면 REDIS_PASSWORD 는 비운다, debug 모드는 끈다
