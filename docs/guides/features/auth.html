라우터(view)는 입력·HTTP 상태와 커밋 시점을, 서비스는 업무 규칙을, 저장소는 DB 표현을 책임집니다. 세션은 의존성(get_writer_db_session·get_read_only_db_session)이 열고, DB 에 쓰는 핸들러만 await service.commit()을 한 번 호출합니다 — register 는 응답 DTO를 검증한 뒤, login 은 토큰 발급 뒤(bcrypt → Argon2 재해시가 있으면 이때 저장). refresh·logout 은 DB 를 쓰지 않고 Redis 원자 연산(RefreshTokenStore)만 하므로 커밋하지 않습니다. 레이트 리밋은 register·login 에만 걸립니다. 예외가 나면 세션 의존성의 정리 단계가 롤백합니다.

사용과 확장

클라이언트는 API 레퍼런스의 접근 수준을 만족한 뒤 OpenAPI 스키마에 맞춰 호출합니다. 외부 IdP를 붙일 때 Principal 계약을 유지하고 토큰 검증 어댑터를 교체합니다.

  1. 요구사항과 접근 정책을 먼저 정합니다.
  2. 스키마 → 서비스 규칙 → 저장소 → 라우터 순서로 책임을 배치합니다.
  3. 마이그레이션과 단위·통합 테스트를 같은 변경에 포함합니다.
  4. API 또는 운영 흐름이 달라지면 이 문서와 전체 API 표를 함께 갱신합니다.

주의점

  • 서비스·저장소는 커밋하지 않습니다. 커밋은 DB 에 쓰는 핸들러(register·login)가 한 번 합니다(tests/test_validate_before_commit.py·app/features/auth/tests/test_transaction_boundary.py). 라우터에서 쿼리를 조립하지 않습니다.
  • 목록 API는 정렬·페이지 경계를 안정적으로 유지합니다.
  • 삭제·수정은 존재 여부와 권한 실패를 구분하되 내부 정보를 과도하게 노출하지 않습니다.
