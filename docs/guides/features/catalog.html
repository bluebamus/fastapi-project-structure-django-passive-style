라우터(view)는 입력·HTTP 상태와 커밋 시점을, 서비스는 업무 규칙을, 저장소는 DB 표현을 책임집니다. 세션은 의존성(get_writer_db_session·get_read_only_db_session)이 열고, 쓰기 핸들러가 응답 DTO를 검증한 뒤 await service.commit()을 한 번 호출합니다. 검증이 실패하면 커밋하지 않고, 예외가 나면 세션 의존성의 정리 단계가 롤백합니다.

사용과 확장

클라이언트는 API 레퍼런스의 접근 수준을 만족한 뒤 OpenAPI 스키마에 맞춰 호출합니다. 재고·가격 이력은 상품 테이블에 누적하지 말고 별도 도메인으로 분리합니다.

  1. 요구사항과 접근 정책을 먼저 정합니다.
  2. 스키마 → 서비스 규칙 → 저장소 → 라우터 순서로 책임을 배치합니다.
  3. 마이그레이션과 단위·통합 테스트를 같은 변경에 포함합니다.
  4. API 또는 운영 흐름이 달라지면 이 문서와 전체 API 표를 함께 갱신합니다.

주의점

  • 서비스·저장소는 커밋하지 않습니다. 커밋은 쓰기 핸들러가 응답 DTO 검증 뒤 한 번 합니다(tests/test_validate_before_commit.py가 고정). 라우터에서 쿼리를 조립하지 않습니다.
  • 목록 API는 정렬·페이지 경계를 안정적으로 유지합니다.
  • 삭제·수정은 존재 여부와 권한 실패를 구분하되 내부 정보를 과도하게 노출하지 않습니다.
