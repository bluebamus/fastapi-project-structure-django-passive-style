6. 테스트와 품질 게이트

개발·확장의 세부 주제입니다. 목적·책임·운영 및 확장 시 지켜야 할 계약을 설명합니다.

6. 테스트와 품질 게이트

6.1 명령

uv sync                                                          # 의존성 (dev 그룹 포함)
uv run python -m pytest -m "not mysql and not browser"           # 외부 인프라 불필요 — CI 기본 job 과 같은 범위
uv run ruff check .
uv run ruff format --check .
uv run mypy .
uv run python -m scripts.bandit_gate                             # Bandit MEDIUM 이상
uv run python -m scripts.review_gate                             # 아래 전 단계 일괄 (--fast: mysql·browser 제외, --list: 목록만)
  • pytest 콘솔 스크립트가 아니라 python -m pytest 를 쓴다(다른 인터프리터를 집어 import 가 어긋난 전례).
  • 단위 테스트는 in-memory SQLite 와 가짜 Redis 를 쓴다. Redis 를 실제로 쓰는 클래스(RefreshTokenStore·RateLimiter)와 그 엔드포인트는 dev 의존성 fakeredis 의 fakeredis.aioredis.FakeRedis 를 생성자에 넣거나 app.dependency_overrides[get_redis] 로 주입해 실물 클래스를 시험한다(가짜 Protocol 을 만들지 않는다, service-hardening ADR-022). 예: app/features/auth/tests/test_endpoint.py. pyproject.toml 이 DEBUG=true, ENV=test 를 주입하고 tests/·app/ 의 test_*.py 를 수집한다(strict marker).
  • 임시 경로를 저장소 안에 두지 않으려면 --basetemp <경로>, mypy --cache-dir <경로> 를 준다. 게이트 판정용 mypy 는 콜드 캐시 결과만 유효하다(CI 는 캐시를 복원하지 않는다).
  • 마커를 빼지 않으면 mysql 테스트는 MySQL 이 없을 때 skip 되지만 browser 테스트는 skip 없이 실패한다.
  • 폐기 경고는 실패다. pyproject.toml 의 filterwarnings 가 error::DeprecationWarning·error::PendingDeprecationWarning 이고 예외(ignore) 목록은 비어 있다. 경고가 뜨면 억제하지 말고 원인을 없앤다(예: 루트 conftest.py 가 Python 3.12 가 폐기한 sqlite3 기본 date/datetime 어댑터를 명시 등록해 해결한다). 못 고칠 예외를 넣어야 하면 왜 못 고치는지를 줄마다 남긴다. UserWarning 은 error 로 올리지 않는다 — StarletteDeprecationWarning 이 이를 상속해서, 켜면 서드파티의 폐기 일정이 이 저장소의 빌드를 잡는다.
마커 준비 실행
mysql docker compose -f compose.test.yaml up -d --wait (MySQL 8.4, 127.0.0.1:3309 — 포트는 환경변수 MYSQL_TEST_PORT 로 변경, tmpfs) uv run python -m pytest -m mysql → 끝나면 docker compose -f compose.test.yaml down -v
e2e Docker(Windows 는 WSL 안) + uv run python -m playwright install chromium. compose 는 하네스가 띄운다(§6.6) REDIS_HOST=127.0.0.1 REDIS_PORT=16393 uv run python -m pytest -m e2e — -m 식에 e2e 가 있을 때만 수집된다
browser uv run python -m playwright install chromium + 위 compose(MySQL 과 함께 Redis 127.0.0.1:6380 이 뜬다 — 포트는 환경변수 REDIS_TEST_PORT 로 변경) REDIS_HOST=127.0.0.1 REDIS_PORT=6380 uv run python -m pytest -m browser — 두 변수가 없으면 실패한다(남의 Redis 에 붙지 않게) — 실제 uvicorn 을 DEBUG=true 로 띄워 Scalar 렌더링 확인

review_gate 단계(순서대로): ruff format → ruff check → mypy → bandit(app·scripts·main.py·config.py, 파싱 실패도 실패) → pip-audit(--strict) → pytest(인프라 제외, 커버리지 측정·하한) → OpenAPI 규칙 fail-on-revert(scripts/openapi_revert_check.py) → pytest -m mysql(skip 금지) → pytest -m browser(skip 금지). 단계 수를 세지 말고 이름으로 가리킨다 — 정본은 scripts/review_gate.py 의 build_steps() 이고 --list 가 현재 목록을 출력한다. --fast 는 마지막 두 단계(pytest -m mysql·pytest -m browser)를 빼고 실행하지 않았다는 경고를 남긴다. 의존성 감사는 외부 인프라가 필요 없고 몇 초면 끝나므로 --fast 에도 남긴다 — 코드가 그대로여도 권고는 새로 뜨고, 그걸 전체 게이트를 돌릴 때까지 몰라야 할 이유가 없다. 도구 stdio 는 UTF-8 로 고정하고 실행별 임시 경로를 쓴다. pytest 단계는 모두 --strict-markers 를 주고 skipped·xfailed·xpassed·"no tests ran" 을 실패로 본다. 커버리지 하한은 pyproject.toml 의 [tool.coverage.report] fail_under 하나다 — CI 와 로컬 게이트 모두 --cov 만 주고 이 값을 읽는다. 기본값은 0(하한 없음) 이다 — 처음에는 기능이 제대로 동작하는지 확인하는 것이 먼저라는 사용자 결정이다(log-redaction-fixes ADR-005). 측정과 term-missing 리포트는 항상 나온다. 하한을 올리는 법: 게이트 출력의 TOTAL 수치를 확인하고 그보다 조금 낮게 fail_under 를 정한 뒤(예: 93% 면 90), 테스트가 늘 때마다 조금씩 올린다. 값은 그 한 곳만 고치고, tests/scripts/test_gates.py::test_coverage_threshold_has_one_source 의 기대값을 함께 바꾼다.

CI (.github/workflows/ci.yml) — 판정 규칙의 정본은 scripts/review_gate.py 이며 두 파일을 함께 고친다.

job 내용
gate uv sync --locked → ruff check·format → mypy(콜드 캐시) → bandit gate → pip-audit(--strict) → pytest 커버리지 측정·하한(fail_under, 기본 0, -m "not mysql and not browser") → skipped·xfailed·xpassed 0건 확인 → OpenAPI 규칙 fail-on-revert → alembic 단일 head → SQLite upgrade head + alembic check
mysql compose 기동 → upgrade head → downgrade -1 → 재-upgrade → alembic check → pytest -m mysql(skip·xfail·0건이면 실패) → Chromium 설치 → pytest -m browser(skip·xfail·0건이면 실패) → down -v
e2e 실행별 무작위 MySQL 비밀번호(마스킹) → Chromium 설치 → pytest -m e2e(하네스가 compose.e2e.yaml 기동·종료, skip·xfail·xpass 가 있거나 0건이면 실패) → 실패 시 앱·worker·MySQL·Redis 로그와 인벤토리 대조표를 artifact 로 업로드 → 항상 compose down

gate·mysql job 의 pytest 단계는 REDIS_HOST·REDIS_PORT 를 명시한다 — 브라우저 하네스는 둘이 없으면 접속 전에 실패한다 (기본 포트로 떨어져 남의 Redis 에 붙는 사고를 막는다, integration-e2e W0).

6.2 테스트 위치

기능 테스트는 app/features/<name>/tests/, 여러 기능·core 계약을 보는 테스트는 최상위 tests/(core/·core/apps/·integration/·browser/·scripts/·utils/). Endpoint 테스트는 dependency_overrides 로 세션·Service 를 바꾸고 종료 시 복원한다. 세션 의존성(get_writer_db_session·get_read_only_db_session)은 손으로 오버라이드하지 않고 tests/session_overrides.py 의 sqlite_session_overrides(app) 를 쓴다 — 운영과 같이 read-only 세션은 mark_read_only, writer 세션은 using_writer 를 거쳐 GET 핸들러의 몰래 쓰기가 테스트에서도 ReadOnlyRoutingError 로 드러난다(커밋 집계는 on_session 훅, 손 오버라이드 금지는 tests/test_session_overrides.py). importlib.reload(config) 를 하는 테스트는 루트 conftest.py 의 restore_config 픽스처로 원래 설정 객체를 되돌리고, alembic 을 부르는 테스트는 config.db_settings 를 호출 시점에 꺼내 patch 한다. lifespan 을 검증할 때는 app.router.lifespan_context 처럼 실제 context 에 진입한다 — ASGITransport 요청만으로 startup 이 검증되지 않는다.

6.6 전수 통합 (e2e)

tests/e2e/ 는 실제 환경 전체를 띄운다 — compose.e2e.yaml(MySQL 8.4 primary 127.0.0.1:13341 + GTID replica :13342 + Redis 7.4 :16393, 프로젝트 itest-passive, 데이터는 tmpfs)과, .env 가 없는 실행 디렉터리에서 ENV=production 으로 띄운 uvicorn(:18093)·Celery worker. 실행마다 비밀번호·JWT 키를 새로 만든다(CI 는 미리 만들어 마스킹한 E2E_* 를 넘긴다).

REDIS_HOST=127.0.0.1 REDIS_PORT=16393 uv run python -m pytest -m e2e    # 전체(약 7분) — 끝나면 compose down
E2E_KEEP_STACK=1 ... -m e2e tests/e2e/test_l2_api_matrix.py              # 파일 하나 + 컨테이너 남기기(디버깅)
  • Windows: Docker 는 WSL 안에만 있어도 된다 — 하네스가 wsl -e docker compose … 를 쓰고 비밀번호는 WSLENV 로 넘긴다. WSL 은 안에 살아 있는 프로세스가 없으면 유휴 종료되며 컨테이너를 함께 죽인다 — 오래 돌릴 때는 wsl -e sleep 7000 같은 keepalive 를 따로 띄워 두고 끝나면 내린다.
  • 안전장치: 하네스는 시작 전에 모든 DSN·Redis 의 host 가 127.0.0.1 이고 포트가 위 값인지 본다 — 아니면 아무 데도 접속하지 않고 멈춘다. MySQL 장애는 컨테이너를 멈추지 않고 offline_mode 로 주입한다(tmpfs 라 stop 하면 스키마가 사라진다).
  • 보장하는 것(층): L2 operation 마다 정상(OpenAPI 스키마·DB 반영)·검증 오류·미인증(401 + WWW-Authenticate)·권한 부족·없음· 잘못된 메서드·선언된 접근 수준 대조 / L3 인증 수명·레이트 리밋·소유권·사용자 변경 시 세션 폐기·접속 로그·보존 삭제(worker)· 매출·Celery 왕복·beat 일정·읽기/쓰기 분리(replica 전용 행·복제 지연) / L4 관리 화면 7 뷰의 목록·상세·생성·수정·삭제·일괄 삭제· 내보내기·날짜 필터 4종·기간 필터 UI, CSRF, 로그아웃, 세션 만료·폐기, ADMIN_DISABLED / L5 Redis·primary·replica·worker 장애와 회복, CSRF 본문 상한(413·400)·측정 / L6 Alembic 왕복, create_superuser, 기동 거부, 로그 경로·파일·회전·레벨, 인증 캐시가 빈 첫 연결 / 마지막에 인벤토리 대조(빈 칸 = 실패)와 로그 비밀값 검사.
  • 새 API·관리 뷰·태스크·Redis 키를 추가하면: 인벤토리 대조기(test_zz_inventory.py)가 앱에서 대상을 다시 뽑으므로, 칸을 채우지 않으면 e2e 가 실패한다. operation 이면 test_l2_api_matrix.py 의 REQUESTS(유효한 요청)와 필요하면 INVALID· OWNERSHIP 에 한 줄씩 더하고, 해당하지 않는 칸은 NOT_APPLICABLE 에 사유와 함께 적는다. 관리 뷰는 test_l4_admin.py 의 VIEWS, 새 Redis 키 리터럴은 그 키를 만드는 시나리오가 실행 중에 한 번은 지나가야 한다.
  • 실패하면 실행 디렉터리(--basetemp 아래 e2e-run*)에 uvicorn·worker 출력, logs/, inventory-table.txt, observations.txt 가 남는다. E2E_ARTIFACT_DIR 을 주면 그리로 복사한다(CI 산출물).
