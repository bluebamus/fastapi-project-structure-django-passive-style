---

## 1. 이 그룹이 푸는 문제

사용자 요구를 그대로 옮기면 이렇다.

> 이 프로젝트 구조를 사용하는 개발자들이, Django 스타일의 app 을 수동으로 인지하는
> 구조, 그리고 raw 쿼리를 사용하는 경우·orm 을 사용하는 경우에 대해 각 워크플로우 및
> 개발 룰을 이해하고 학습할 수 있기를 원한다.

검수 결과 **두 주제 중 하나만 달성**돼 있다.

| 주제 | 상태 |
|---|---|
| Django 스타일 수동 등록 | ✅ 달성 — 진입 문서 3종 + 심화 문서 |
| ORM/Raw 워크플로 | ❌ 미달성 — `RawRepositoryBase` 가 진입 문서 3종에 **0회** |
| 심화 가이드 정확성 | ❌ **틀림** — `project-guide` 가 존재하지 않는 세션 API 3개를 가르친다 (L-007) |

만든 것이 잘못된 게 아니다. **만든 것과 가르치는 것 사이가 끊겼다.**
Phase 4~7 의 산출물이 CRP·설계 문서에만 기록됐고, 학습자가 읽는 문서는 Phase 3 에 멈춰 있다.

---

## 2. 범위

### 2-1. 목표

1. 학습자가 **진입 문서만 읽고도** ORM/Raw 두 계층의 존재와 선택 기준을 안다
2. `docs/project-guide/` 가 현재 코드(Phase 7 기준)를 반영한다
3. 그 상태가 **기계 검사로 잠긴다** — 다음 Phase 에서 또 끊기지 않도록

### 2-2. 비목표

- **코드 변경** — 검수에서 코드 층은 문제없음으로 확인됐다(§7 참고)
- **설계 문서 이동** — `docs/orm-raw-repository/2026-08-13/` 는 설계 문서로 완결돼 있다.
  학습 문서가 그 내용을 **대상 독자에 맞게 다시 쓰는** 방향이지, 옮기는 것이 아니다
- **Django 스타일 문서 보강** — 이미 달성됐다. 건드리면 손해다
- 새 기능·새 예제 추가

## 3. 불변식 (작업 중 깨면 안 되는 것)

- **INV-L1**: 코드는 바뀌지 않는다. 이 그룹의 diff 는 문서와 테스트에만 나타난다
  (예외: T-3 의 새 검사 파일)
- **INV-L2**: `scripts/review_gate.py` 8단계가 계속 통과한다
  — 단, T-4a 착수 직후는 의도적으로 빨갛다. T-4a 와 T-1 을 **한 커밋으로 묶어**
  중간 상태를 남기지 않는 것으로 이 불변식을 지킨다
- **INV-L3**: `docs/project-guide/v1.0/` 은 **지우지 않는다**. `v1.1` 을 새로 만든다
  (버전 폴더 규약)
- **INV-L4**: 학습 문서가 설계 문서를 복사하지 않는다. 대상 독자가 다르므로 다시 쓴다

## 4. GATE 3 인수 기준

`audit-report.md` §5 를 그대로 쓴다. 요약하면:

- `RawRepositoryBase` 가 진입 문서 **최소 2곳**

- "언제 ORM, 언제 Raw" 가 **학습 문서**에 존재
- 진입 문서 → `project-guide` 링크 존재
- 새 검사가 **fail-on-revert 로 동작 증명**
- 게이트 8단계 통과

## 5. 착수 방법

다음 세션은 이렇게 시작하면 된다.

1. `audit-report.md` 를 읽는다 — 무엇이 왜 문제인지, 무엇을 해야 하는지가 다 있다
2. §6 의 순서(**T-4a → T-1 → T-2 → T-3**)를 따른다 — 2026-08-20 재검수에서 검사 확대가 맨 앞으로 왔다
3. 이 그룹의 `design-baseline.md`·`ledger.md`·`run-log.md`·`checklist.md`·
   `residual-risk.md` 는 아직 없다. 착수 시 `orm-raw-repository` 그룹의 것을
   참고해 만든다(같은 CRP 템플릿)

**T-1 을 먼저 하는 이유**: T-2 는 "어디를 가리킬지", T-3 은 "무엇을 잠글지" 가
정해져야 쓸 수 있다. 반대로 하면 두 번 고친다.
