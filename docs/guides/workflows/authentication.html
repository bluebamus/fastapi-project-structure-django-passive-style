PROJECT GUIDE

API JWT 인증

가입·로그인·보호 API·refresh 회전·로그아웃의 경계와 실패 원칙을 설명합니다.

허브부팅설계 API요청인증 기능개발운영

도식은 고정 버전 Mermaid CDN(11.12.0)을 사용합니다. 인터넷이 없어도 본문·표·도식 원문을 읽을 수 있습니다.

인증 모델

API는 Bearer JWT를 사용하고, 짧은 수명의 access token과 서버 저장소에서 상태를 관리하는 refresh token을 분리합니다. 관리자 화면의 쿠키 세션은 별도 경계이므로 서로 대체하지 않습니다.

보안 의도와 확장

  • refresh token 회전은 탈취 토큰의 재사용 창을 줄입니다. 저장소 오류를 성공으로 간주하지 않습니다.
  • 로그인·가입만 rate limit 대상입니다(refresh·logout은 공개 쓰기지만 rate limit이 없습니다).
  • access token은 만료(기본 15분) 전에 폐기할 수 없습니다. 비활성화·강등·삭제는 refresh family와 관리 세션을 지우지만 이미 받은 access는 만료까지 유효합니다.
  • /me만 DB에서 사용자를 다시 읽습니다. 다른 보호 경로는 토큰 클레임(sub·su)만 보므로 권한 강등은 access 만료 뒤에 반영됩니다.
  • 라우트 접근 수준과 리소스 소유권을 분리해 owner/superuser 정책을 재사용합니다.
  • 외부 IdP를 추가할 때도 내부 Principal과 접근 수준 계약은 유지합니다.
