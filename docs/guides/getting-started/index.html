PROJECT GUIDE

부팅과 첫 실행

설정 준비부터 readiness와 정상 종료까지 실제 기동 경로를 설명합니다.

허브부팅설계 API요청인증 기능개발운영

도식은 고정 버전 Mermaid CDN(11.12.0)을 사용합니다. 인터넷이 없어도 본문·표·도식 원문을 읽을 수 있습니다.

목적

개발 환경을 재현하고 데이터베이스 스키마를 적용한 뒤 API 프로세스를 안전하게 시작하는 절차입니다. 설정 검증은 config.py를 import 하는 시점에 끝나고(실패하면 lifespan 전에 멈춤), Redis 연결 확인과 개발용 테이블 생성은 lifespan 안에서 실행됩니다.

필수 절차

  1. uv sync로 잠금 파일 기준 의존성을 설치합니다.
  2. .env.example을 .env로 복사합니다. ACCESS_TOKEN_SECRET_KEY·REFRESH_TOKEN_SECRET_KEY·SESSION_SECRET_KEY를 서로 다른 32자 이상 값으로 바꾸고(uv run python -c "import secrets; print(secrets.token_urlsafe(48))"), MYSQL_PASSWORD를 실제 값으로 바꿉니다. 예시 값 그대로면 개발 환경에서도 기동하지 않습니다.
  3. Redis 7.0 이상을 띄웁니다. Redis는 필수 기동 조건입니다 — ping()이 실패하거나 7.0 미만이면 서버가 시작하지 않습니다(DEBUG와 무관).
  4. MySQL을 띄웁니다. DEBUG=true(기본)면 startup에서 설치 앱이 소유한 테이블을 create_all로 만들므로 MySQL이 필요합니다. 운영처럼 하려면 uv run alembic upgrade head 후 DEBUG=false로 실행합니다.
  5. uv run uvicorn main:app --reload --port 8000(또는 uv run python main.py)로 서버를 실행합니다.
  6. /admin을 쓰려면 uv run python -m scripts.create_superuser --username admin --email admin@example.com으로 슈퍼유저를 만듭니다.
  7. GET /health(생존)와 GET /ready(writer DB SELECT 1 + Redis PING, 하나라도 실패하면 503)를 구분해 확인합니다.

단계별 명령과 막히는 지점은 README 빠른 시작이 정본입니다.

실패를 읽는 법

  • 설정 오류(설정이 안전하지 않습니다)는 config import 때 나므로 메시지에 나온 설정 이름을 고칩니다.
  • DEBUG=false이거나 소유 테이블이 0개면 기동 중 DB에 접속하지 않습니다. 그래서 MySQL 없이도 뜨고, /ready가 503, 기능 API가 500이 됩니다. 마이그레이션과 모델이 어긋나면 요청 시점에 실패합니다(/ready는 SELECT 1만 봅니다).
  • Redis는 기동 필수입니다. 실행 중 Redis가 끊기면 Redis를 쓰는 경로(가입·로그인·refresh·logout·사용자 비활성화·강등·삭제, /admin)가 503을 내고 /ready도 503이 됩니다. Redis를 쓰지 않는 조회는 그대로 동작합니다.
  • 프로세스 종료 시 새 요청 수락을 멈추고 진행 중 작업과 연결 풀 정리를 기다립니다.
