접근 로그 기능

요청 관측 정보를 비동기 저장하고 운영 조회 API로 노출합니다.

허브부팅설계 API요청인증 기능개발운영

도식은 고정 버전 Mermaid CDN(11.12.0)을 사용합니다. 인터넷이 없어도 본문·표·도식 원문을 읽을 수 있습니다.

목적과 책임

요청 관측 정보를 비동기 저장하고 운영 조회 API로 노출합니다.

이 기능의 API는 조회만 하므로 커밋하지 않습니다. 세션은 의존성(get_read_only_db_session)이 엽니다.

보존 삭제와 통계 태스크

app/features/home/tasks.py의 Celery 태스크가 요청 밖에서 background_session()으로 세션을 엽니다.

  • home.purge_expired_access_logs — ACCESS_LOG_RETENTION_DAYS(기본 365, 0이면 삭제 안 함)보다 오래된 접속 로그를 배치마다 커밋하며 지웁니다. Celery beat가 매일 03:30(TIME_ZONE)에 보냅니다 — beat를 띄우지 않으면 돌지 않습니다.
  • home.aggregate_access_stats — 접속 로그 통계를 집계해 반환하는 예시 태스크입니다(beat 일정 없음).

운영 절차는 README 운영 배포 체크리스트의 접속 로그 보존 항목을 따릅니다.

사용과 확장

클라이언트는 API 레퍼런스의 접근 수준을 만족한 뒤 OpenAPI 스키마에 맞춰 호출합니다. 보존 기간과 개인정보 마스킹 정책을 먼저 정한 뒤 통계 집계를 확장합니다.

  1. 요구사항과 접근 정책을 먼저 정합니다.
  2. 스키마 → 서비스 규칙 → 저장소 → 라우터 순서로 책임을 배치합니다.
  3. 마이그레이션과 단위·통합 테스트를 같은 변경에 포함합니다.
  4. API 또는 운영 흐름이 달라지면 이 문서와 전체 API 표를 함께 갱신합니다.

주의점

  • 라우터에서 쿼리를 조립하지 않습니다. 조회 API에 커밋을 추가하지 않습니다.
  • 목록 API는 정렬·페이지 경계를 안정적으로 유지합니다.
  • 삭제·수정은 존재 여부와 권한 실패를 구분하되 내부 정보를 과도하게 노출하지 않습니다.
