PROJECT GUIDE

아키텍처 — INSTALLED_APPS 조립

기능 경계, 계층 책임, 의존 방향과 조립 방식을 설명합니다.

허브부팅설계 API요청인증 기능개발운영

도식은 고정 버전 Mermaid CDN(11.12.0)을 사용합니다. 인터넷이 없어도 본문·표·도식 원문을 읽을 수 있습니다.

설계 의도

config.INSTALLED_APPS에 적힌 AppConfig 경로로 App Registry가 채워지고, create_app()이 설치된 앱의 Router·Models·Admin을 조립합니다. 앱을 더하거나 뺄 때 main.py·migrations/env.py는 고치지 않습니다.

기능은 app/features/<name> 아래에서 API, 서비스, 저장소, 모델, 스키마를 함께 소유합니다. 공통 인프라만 app/core로 올려 기능 간 결합을 줄입니다.

라우터(view)는 HTTP 변환·의존성 선언과 커밋 시점을, 서비스는 유스케이스를, 저장소는 영속성 세부사항을 담당합니다. 세션은 의존성이 열고, 쓰기 핸들러가 응답 DTO 검증 뒤 await service.commit()을 한 번 호출합니다. 저장소가 HTTP 예외를 만들거나 라우터가 직접 쿼리를 조합하지 않는 것이 핵심입니다.

적용 패턴

패턴목적확장 시 주의
수직 슬라이스기능별 변경 범위를 한 디렉터리에 모음공통 코드로 너무 일찍 승격하지 않음
RepositoryORM/Raw SQL을 서비스에서 격리저장소·서비스는 커밋하지 않음(커밋은 쓰기 핸들러)
Dependency Injection세션·서비스·Principal을 요청 단위로 제공전역 mutable 상태 금지
Policy/Principal인증과 리소스 소유권 판단 분리라우트마다 Public·PublicWrite·LoginRequired·SuperuserRequired 중 하나를 선언(없으면 AccessPolicyGuard가 기동 거부)
Lifespan시작·종료 자원 관리 일원화import 시점 I/O 금지
