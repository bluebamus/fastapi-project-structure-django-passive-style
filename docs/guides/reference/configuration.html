PROJECT GUIDE

환경 설정 레퍼런스

config.py의 설정 모델 전체와 기동 시 검증 규칙을 정리합니다.

허브부팅설계 API요청인증 기능개발운영

도식은 고정 버전 Mermaid CDN(11.12.0)을 사용합니다. 인터넷이 없어도 본문·표·도식 원문을 읽을 수 있습니다.

사용 원칙

설정의 단일 진입점은 config.py이며 환경 변수 이름과 예시는 .env.example에서 확인합니다. 운영 비밀은 저장소에 커밋하지 않고 비밀 관리 시스템에서 주입합니다.

설정 검증 규칙

검증은 config.py를 import 하는 시점에 돌고, 실패하면 lifespan에 들어가기 전에 프로세스가 멈춥니다. ENV=test(pytest가 지정)는 아래 비밀값·출처 검사를 건너뜁니다.

  • ACCESS_TOKEN_SECRET_KEY·REFRESH_TOKEN_SECRET_KEY·SESSION_SECRET_KEY — 개발 환경을 포함해 placeholder(빈 값, your-로 시작, change-this 포함)이거나 32자 미만이면 거부합니다. access·refresh 키가 같아도 거부합니다.
  • MYSQL_PASSWORD — 빈 값이나 placeholder면 거부합니다. REDIS_PASSWORD는 값이 있을 때만 placeholder인지 봅니다(인증 없는 Redis는 비워 둡니다).
  • ENV가 staging·production이면 DEBUG=true, LOG_LEVEL=DEBUG, LOG_SQL_ECHO_ENABLED=true를 거부합니다.
  • .env가 없으면 ENV·비밀 키 3종·MYSQL_HOST·MYSQL_USER·MYSQL_PASSWORD·MYSQL_DATABASE가 환경 변수로 모두 있어야 합니다.
  • 제거된 ADMIN 설정이 환경이나 .env에 남아 있으면 거부합니다(ADMIN_DISABLED로 옮깁니다).
  • 클래스별 검증 — DB_REPLICATION_ENABLED=true는 DB_ROUTER_ENABLED=true와 replica 호스트 1대 이상이 필요합니다. DB_MAX_SERVER_CONNECTIONS를 주면 총 연결 수가 그 값을 넘지 않아야 합니다. CORS_ALLOW_CREDENTIALS=true와 CORS_ALLOW_ORIGINS=["*"]는 함께 쓸 수 없습니다. ADMIN_SESSION_*는 60 이상이고 미사용 만료가 절대 만료 이하여야 합니다. SESSION_COOKIE_NAME은 admin_session일 수 없습니다. 로그 포맷·LOG_APP_LEVELS·LOG_DATE_FORMAT 형식도 검사합니다.

확장 방법

  1. 설정 필드를 타입과 안전한 기본값으로 추가합니다.
  2. .env.example에는 비밀이 아닌 예시와 설명을 추가합니다.
  3. 서로 의존하는 값은 설정 검증 단계에서 빠르게 실패시킵니다.
  4. 배포 매니페스트와 테스트 fixture를 함께 갱신합니다.
