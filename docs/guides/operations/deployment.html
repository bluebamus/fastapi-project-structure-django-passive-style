PROJECT GUIDE

배포와 운영

설정, migration, readiness, 관측, 정상 종료를 연결한 운영 체크리스트입니다.

허브부팅설계 API요청인증 기능개발운영

도식은 고정 버전 Mermaid CDN(11.12.0)을 사용합니다. 인터넷이 없어도 본문·표·도식 원문을 읽을 수 있습니다.

배포 전 필수 확인

전체 목록의 정본은 README 운영 배포 체크리스트와 아키텍처 §11.1입니다. 이 페이지는 요약입니다.

  • ENV=staging 또는 production으로 둡니다. 이때 DEBUG=true·LOG_LEVEL=DEBUG·LOG_SQL_ECHO_ENABLED=true면 기동이 거부되고, /admin 쿠키에 Secure가 붙어 HTTPS가 필요합니다.
  • DB·Redis 접속은 개별 키로 주입합니다: MYSQL_HOST·MYSQL_PORT·MYSQL_USER·MYSQL_PASSWORD·MYSQL_DATABASE, REDIS_HOST·REDIS_PORT·REDIS_DB·REDIS_PASSWORD. URL 형식은 Alembic 전용 ALEMBIC_DATABASE_URL(선택)뿐입니다.
  • 비밀 키 3종(ACCESS_TOKEN_SECRET_KEY·REFRESH_TOKEN_SECRET_KEY·SESSION_SECRET_KEY)은 서로 다른 32자 이상 무작위 값을 비밀 저장소에서 주입합니다. .env 없이 환경 변수로만 주입하면 ENV·비밀 키 3종·MYSQL_HOST/USER/PASSWORD/DATABASE가 모두 있어야 합니다.
  • 프록시 뒤라면 TRUSTED_PROXY_HOPS를 앞단 프록시 단 수로 둡니다. 0이면 모든 사용자가 프록시 IP 하나로 보여 로그인 rate limit을 함께 씁니다. 실제보다 크면 IP를 위조할 수 있습니다.
  • 시각 마이그레이션 리비전 e5a7c2d9f310은 기존 MySQL 시각을 KST(+09:00)로 가정합니다. 다른 시간대였다면 LEGACY_OFFSET을 바꾸고, 적용 전에 백업합니다. 그다음 uv run alembic upgrade head를 rollout과 호환되는 순서로 실행합니다.
  • 첫 관리자는 scripts/create_superuser.py로 만듭니다. 관리 화면을 쓰지 않으면 ADMIN_DISABLED=true로 끕니다.
  • Redis 7.0 이상이어야 합니다. 접속 로그 보존 삭제는 Celery worker와 beat(하나만)를 띄워야 돕니다.
  • uvicorn --workers 2 이상이거나 Celery prefork면 LOG_FILE_ENABLED=false로 두고 stdout을 수집합니다(파일 회전은 한 프로세스 전용).
  • /health는 생존, /ready(writer DB SELECT 1 + Redis PING)는 트래픽 수신 가능 여부에 씁니다.

운영 관측과 장애 대응

  • 요청 상관용 ID는 없습니다. 예외 로그의 path·method와 접속 로그(client IP·경로·상태·user_id)·시각으로 대조합니다.
  • 5xx 증가, readiness 실패, DB pool 고갈, Redis 오류, task 적체를 알림 대상으로 둡니다.
  • Redis 장애 중에는 Redis를 쓰는 경로(가입·로그인·refresh·logout·사용자 비활성화·강등·삭제, /admin)가 503을 내고 /ready가 503이 됩니다. Redis가 돌아오면 재시작 없이 회복합니다. 인증 저장소 오류를 허용으로 우회하지 않습니다(fail-closed).
  • 종료 grace 기간은 실제 가장 긴 정상 요청과 background 정리 시간을 근거로 정합니다.
