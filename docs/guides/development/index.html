PROJECT GUIDE

개발 가이드

기능을 추가·변경할 때 계층, DI, 트랜잭션, 문서를 함께 완성하는 순서입니다.

허브부팅설계 API요청인증 기능개발운영

도식은 고정 버전 Mermaid CDN(11.12.0)을 사용합니다. 인터넷이 없어도 본문·표·도식 원문을 읽을 수 있습니다.

새 기능 추가

  1. app/features/<name> 안에 기존 기능과 같은 수직 구조를 만듭니다.
  2. 읽기/쓰기 세션, 공개/로그인/관리자 접근 수준, 소유권 규칙을 명시합니다.
  3. config.INSTALLED_APPS 끝에 "app.features.<name>.apps.<Name>Config" 한 줄을 붙입니다. Router·Models·Admin은 AppConfig가 선언한 규약대로 함께 켜집니다. 뷰마다 접근 수준을 선언하지 않으면 AccessPolicyGuard가 기동을 거부합니다(기본 거부).
  4. 모델 변경이면 Alembic migration을 만들고 upgrade/downgrade를 검증합니다.
  5. 단위 테스트 후 문서·링크·OpenAPI operation 수를 확인합니다.

코드 리뷰 기준

  • 업무 규칙이 라우터나 저장소로 새지 않았는가
  • 쓰기 핸들러가 응답 DTO 검증 뒤 await service.commit()을 한 번만 호출하는가(서비스·저장소는 커밋하지 않음)
  • 인증 실패, 권한 실패, 없음, 충돌이 일관된 오류 계약을 따르는가
  • 비동기 함수 안에 블로킹 I/O가 추가되지 않았는가
  • 새 공개 API와 설정이 문서화되었는가
