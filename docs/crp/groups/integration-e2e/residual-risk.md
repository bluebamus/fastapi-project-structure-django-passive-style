# Residual Risk — integration-e2e (잔여 위험 등록부)

> **재기 금지 목록.** 고쳐야 하면 새 결함이 아니라 **계약 변경 제안** — charter 를 먼저 바꾼다.

| ID | 항목 | Severity | 왜 비범위인가 | 수용일 | 재평가 조건 |
|---|---|---|---|---|---|
| R-001 | CSRF 미들웨어가 토큰 없는 폼 본문 전체를 메모리에 읽는다 — 50 MiB 본문에 최대 RSS +101~109 MiB, 상한 없음(ledger F-007 ①) | MED | 계획서 §5-2: 측정만 하고 상한은 사용자가 정한다 | 2026-10-20 | 사용자가 상한(예: 관리 폼 1~10 MiB, 초과 413)을 정하면 미들웨어 앞에서 `Content-Length`·누적 길이로 자른다 |
| R-002 | 폼 필드 하나가 1 MiB 를 넘으면 500 + 연결 끊김(Starlette 필드 상한 예외가 CSRF 미들웨어 안에서 터진다, F-007 ②) | MED | 응답 코드(400/413)와 R-001 상한을 함께 정해야 한다 — 정책 결정 | 2026-10-20 | R-001 결정과 함께 처리 |
| R-003 | 복제 지연 중 가입 직후 `/me` 가 유효한 토큰에 401(F-008) | MED | 읽기 라우팅(요청 간 sticky 없음)과 인증 응답 의미를 바꾸는 결정 | 2026-10-20 | 사용자가 "인증 주체 확인은 primary" 또는 "없으면 503/404" 를 정하면 `get_current_user` 의 세션을 바꾼다 |
| R-004 | Redis 장애 때 관리 화면 쿠키 없는 첫 요청은 500(응답 직전 세션 저장 실패, F-009) | LOW | 문서화된 현행 — 503 으로 바꾸는 것은 관리 화면 장애 응답 정책 변경 | 2026-10-20 | 정하면 `RedisSessionMiddleware` 의 저장 단계에서 503 으로 바꾼다 |
| R-005 | 422 의 실제 형식과 OpenAPI 광고가 다르다(F-010) | LOW | 응답 형식·OpenAPI 계약 변경 | 2026-10-20 | 클라이언트 생성기를 쓰게 되면 422 응답 스키마를 `ErrorResponse` 로 덮어쓴다 |
| R-006 | PublicWrite 인증 operation 의 401 에 `WWW-Authenticate` 없음(F-012) | LOW | 로그인·refresh 의 오류 응답 의미 변경 | 2026-10-20 | 표준 OAuth2 클라이언트 호환이 필요해지면 |
| R-007 | Windows 에서는 Celery worker 가 `solo` 풀이고 하네스의 종료가 강제 종료라 Warm shutdown 로그가 없다 | LOW | 플랫폼 한계 — Linux(prefork)에서 확인한다 | 2026-10-20 | — |
| R-008 | Redis 키 접두어 인벤토리는 운영 코드의 키 **리터럴**(f-string)을 정규식으로 뽑는다 — 문자열을 조립하는 새 방식이면 놓친다 | LOW | 현재 키는 모두 리터럴이다 | 2026-10-20 | 키 생성 방식을 바꾸면 추출기도 바꾼다 |
