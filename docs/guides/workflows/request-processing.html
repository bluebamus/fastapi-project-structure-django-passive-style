PROJECT GUIDE

API 요청 처리

클라이언트 요청이 미들웨어, 인증, 서비스, DB 세션을 지나 응답이 되는 순서입니다.

허브부팅설계 API요청인증 기능개발운영

도식은 고정 버전 Mermaid CDN(11.12.0)을 사용합니다. 인터넷이 없어도 본문·표·도식 원문을 읽을 수 있습니다.

설계 목적

HTTP 경계의 관측·보안·오류 변환과 기능 유스케이스를 분리합니다. 공통 미들웨어는 모든 요청에 필요한 정보만 다루고, 권한과 비즈니스 규칙은 의존성과 서비스가 맡습니다.

트랜잭션과 오류

  • 기능 라우터의 조회는 get_read_only_db_session, 쓰기는 get_writer_db_session으로 연 세션을 씁니다(get_routed_db_session은 기능 라우터가 쓰지 않습니다). 쓰기 핸들러가 응답 DTO 검증 뒤 await service.commit()을 한 번 호출하고, 예외면 세션 의존성의 정리 단계가 롤백합니다.
  • 미들웨어는 바깥부터 answer_unhandled_exception → UserInfoMiddleware → CORS 순서입니다(마지막에 등록한 것이 가장 바깥).
  • 도식의 수집·저장은 ACCESS_LOG_ENABLED=true 이고 ACCESS_LOG_EXCLUDE_PATHS(정확 일치)·ACCESS_LOG_EXCLUDE_EXTENSIONS(접미사 일치)에 걸리지 않는 요청에만 일어납니다. 나머지는 UserInfoMiddleware 가 그대로 통과시킵니다.
  • Redis 연결·시간 초과 오류는 503 SERVICE_UNAVAILABLE로 응답합니다(가입·로그인·refresh·logout 등 Redis를 쓰는 경로).
  • 이 앱이 내는 401은 모두 WWW-Authenticate: Bearer를 싣습니다.
  • 예상 가능한 애플리케이션 오류는 공통 오류 응답으로 변환합니다.
  • 처리하지 못한 예외의 마지막 방어선은 app/core/bootstrap.py의 answer_unhandled_exception입니다. 내부 정보는 응답에 노출하지 않고 서버 로그에 traceback을 남깁니다. SQLAlchemyError는 SQL·바인딩 값 유출을 막으려고 traceback 없이 예외 종류와 드라이버 코드만 남깁니다. DEBUG=true면 이 미들웨어가 예외를 다시 던집니다.
  • 접근 로그 저장 실패가 주 요청의 성공 응답을 뒤집지 않도록 비동기 sink 경계를 둡니다.
